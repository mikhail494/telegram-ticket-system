# Support

## Bugs and feature requests

Use GitHub Issues for reproducible bugs and feature requests. Include the affected version or commit, deployment type, reproduction steps, expected behavior, actual behavior, and redacted logs when relevant.

Before opening a new issue, check whether the same problem has already been reported.

## Security issues

Do not report suspected vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting or Security Advisories when available.

## Sensitive data

Never attach or paste:

- bot tokens or `.env` contents
- SSH keys or deployment credentials
- SQLite databases or backups
- ticket exports, transcripts, or answer packages containing real support data
- private Telegram messages, user identifiers, or unredacted screenshots

Replace sensitive values with clearly marked placeholders before sharing diagnostics.

## Deployment support

Repository issues are best suited to problems that can be reproduced from the codebase. VPS, firewall, reverse-proxy, Telegram group administration, and other environment-specific operational support is best effort unless the problem can be traced to repository behavior.
